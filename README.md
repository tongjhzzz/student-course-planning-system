# 智能课程规划系统实验报告

## 1. 项目背景与目标
高校课程规划通常需要同时考虑培养方案、课程先修关系、课程类别学分、开课学期、教学班时间冲突、每学期学分负
载以及学生个人偏好。请围绕“智能选课规划”设计并实现一个数据结构项目：系统能够组织课程数据，并在给定专业目
标和约束后生成一份可检查、可解释的八学期课程安排或选课建议

该项目设计了一个智能课程规划系统，可以读取给出的相关课程的信息，以及个人偏好设置，比如特定不想上课的时间，以及手动选课。为了实现一个有一定实用性的，可以根据专业培养方案生成八学期课程安排，并且保证了课程的先修关系，时间上的冲突，满足了每学期的学分，总学分和选修学分的规定
## 2. 需求分析
学生在进行多学期选课规划的时候，要考虑的点太多了，自己慢慢研究费事费力，就诞生了这个项目，当然这个是我的作业
## 3. 系统总体设计
```text
课程 CSV 数据 ─┐
培养方案 JSON ─┼─→ 数据读取与转换 ─→ 排课算法与规则校验 ─→ 课程规划结果
用户时间偏好 ─┤                                      │
手动选课方案 ─┘                                      ↓
                                              Qt 图形化界面展示
                                                      ↓
                                               CSV 文件导出
```
从 `course_info.csv` 和 `course_time.csv` 中读取课程基础信息、教学班信息及上课时间；从 `data/major_profiles/` 中读取不同专业的培养方案；同时通过 JSON 文件保存用户设置的时间偏好和手动选课方案

算法是系统的核心，负责将培养方案和用户输入转换为具体的课程规划约束，并生成八学期课程安排
- 该部分主要处理以下内容
- 课程开设学期与建议修读学期
- 课程之间的先修关系
- 同一学期课程的时间冲突
- 每学期最低、最高学；
- 总学分与专业选修学分
- 用户设置的“尽量避开上课时间”
- 用户手动指定的课程、教学班和目标学期

图形化交互层使用 Qt Widgets 实现，主窗口由 `MainWindow`负责组织
界面主要包括：
- 培养方案选择与生成入口：选择专业培养方案并生成八学期规划
- 八学期课表页面：以周课表形式展示课程安排
- 课程查询页面：支持按关键字、类别、院系、开课季节和学分范围筛选课程
- 我的选课方案页面：用于查看、保存、取消和清空手动选择的教学班
- 时间偏好页面：用于设置并保存希望尽量避开的上课时间
- 规划问题或提示区域：展示未满足的约束、排课失败原因或时间偏好提示

系统生成规划后，会在界面中显示每个学期的课程表、学期学分、总学分和专业选修学分
你也可以将当前规划结果导出为 CSV 文件

## 5. 核心数据结构设计
1. 上课时间结构`TimeSlot`
`TimeSlot` 用于表示一个具体的上课时间段，主要包含
- `day`：上课星期，使用 0～6 分别表示周一至周日
- `beginPeriod`：开始节次
- `duration`：持续节数

2. 基础课程结构`Course`
`Course`表示一门基础课程本身的公共信息，不区分具体教学班。
其主要信息包括：
- `basicId`	基础课程编号，对应数据文件中的 course_basic_ID
- `name`	课程名称
- `department`	开课院系
- `semester`	开课季节，即秋季学期或春季学期
- `recommendedTerm`	建议或最早修读学期
- `category`课程类别，如专业必修课、学科基础课或专业选修课
- `credit`课程学分
- `beginWeek`开始上课周次
- `durationWeeks`持续上课周数
- `prerequisiteIds`先修课程编号列表

3. 教学班结构`CourseSection`
`CourseSection`表示某一基础课程的一个具体教学班
- `basicId`	所属基础课程编号
- `sectionId`教学班编号，对应 course_sp_ID
- `teacher`	授课教师
- `classroom`上课教室
- `capacity`教学班人数上限
- `timeSlots`该教学班的全部上课时间段

4. 培养方案约束结构`PlanningConstraints`
`PlanningConstraints` 用于保存从专业培养方案 JSON 文件中读取出的约束信息
主要包括：
- 专业信息	培养方案编号、名称、描述、目标院系等
- 必修课程	该专业必须完成的课程编号集合
- 选修候选课程	可用于满足选修学分要求的课程编号集合
- 学期学分要求	第 1 至第 8 学期分别对应的最低、最高学分
- 总学分要求	完成培养方案所需的最低总学分
- 选修学分要求	专业选修课最低学分
- 时间约束	培养方案中定义的避开时间段

5. 用户手动选课结构`ManualCourseSelection`
`ManualCourseSelection`用于保存用户手动加入方案的一门具体课程
其内容较简单：
- `basicId`	用户选择的基础课程编号
- `sectionId`用户选择的教学班编号
- `term`用户指定的目标学期

6. 时间偏好结构 `TimePreferenceBlock`
`TimePreferenceBlock`用于表示用户或培养方案指定的时间偏好。其主要成员包括：
- `day`	星期，使用 0～6 表示周一至周日
- `beginPeriod`	开始节次
- `duration`持续节数
- `hard`是否为严格约束
- `reason`	设置该偏好的原因说明

## 6. 核心算法设计
算法整体采用“拓扑排序 + 贪心算法”的思路：先利用拓扑排序保证先修顺序，再按该顺序逐门课程放入最早可行的学期。所有并列选择都按固定规则（建议学期、教学班代码字典序）排序，保证同样的输入一定得到同样的课表，便于检查和复核

1. 算法输入与输出

输入由 `ScheduleConstraints` 结构保存，主要包括：
- 必修课程集合与选修候选池（基础课程编号列表）；
- 第 1~8 学期每学期的最低、最高学分；
- 总学分下限与专业选修课学分下限；
- 用户手动选课列表，算法必须按指定教学班、指定学期固定安排

输出由 `ScheduleResult` 结构保存，主要包括：
- `success`：规划是否完全满足约束；
- `coursesByTerm`：第 1~8 学期各自的教学班安排；
- `creditByTerm`、`totalCredit`、`electiveCredit` 等学分统计；
- `problems`：导致规划未完全满足约束的原因说明；
- `warnings`：不影响成功判定的提示

2. 总体流程

- 第一步：固定手动选课，必须按指定教学班、指定学期放入课表；放不进去就明确报错，不换班也不换学期
- 第二步：反向推导最晚学期。手动课程固定在第 t 学期时，它的先修课必须排在第 t-1 学期或更早。算法沿先修边反向传播，为每门先修课算出允许安排的最晚学期。同时从必修课出发，把缺失的先修课全部补入待排课程集合；先修课无法安排的，逐层向外传播，标记其后继课程同样无法安排
- 第三步：拓扑排序并安排必修课。使用 Kahn 算法对课程先修关系图做拓扑排序，无法入排的课程即为先修依赖环，记入问题列表，从前向后找第一个可行学期。
- 第四步：补足每学期最低学分。依次检查第 1~8 学期，学分不足的从选修候选池中按拓扑序挑选课程补入，候选课必须本学期可开、先修课已排在更早学期、不超学分上限且时间不冲突；补完后仍不足的记入问题列表
- 第五步：补足专业选修学分和总学分。先从候选池中挑选课程类别为“专业选修课”的课程补足选修学分（同时计入总学分），再用整个候选池补足总学分
- 第六步：全局复查先修顺序。所有课程排完后统一检查每门课的先修课是否都排在更早学期，作为前面各步骤的兜底验证
- 第七步：汇总统计并判定。统计总学分、必修与选修学分，只有必修课全部安排、每学期最低学分达标、专业选修学分和总学分达标、手动选课无问题且先修顺序无误时，才算成功

3. 教学班选择策略

为一门课程在某个学期挑选教学班时，按以下顺序处理：

1. 排除与该学期已排课程时间冲突的教学班；
2. 排除禁止时间的教学班；
3. 在剩余教学班中，与“尽量避开”时间重叠数量越少越优先；
4. 重叠数量相同时按教学班代码字典序选择，保证结果确定

4. 时间冲突判定

两门课程同时满足以下两个条件才判定为时间冲突：

- 上课周次有交集，即一门课的开始周不晚于另一门课的结束周；
- 上课时间段在星期和节次上重叠，由 `TimeSlot::overlaps` 判断。
周次不重叠的课程即使节次重叠也不算冲突。

5. 约束的分级处理

算法把约束分为两级：

- 硬约束：手动选课、先修顺序、开课季节、学期学分上限、严格禁止时间。任何一项不满足都会导致对应课程无法安排，并在 `problems` 中给出具体原因；
- 软约束：用户设置的尽量避开时间。软约束只影响教学班的挑选优先级，不会阻止排课。实在避不开时照常安排，并在 `warnings` 中提示“已选择冲突最少的教学班”。

这样设计既允许用户表达个人偏好，也避免由于偏好限制过多而无法生成完整课表。

6. 可解释性设计

每一次安排失败都会记录可归因的原因，例如“受每学期学分上限限制”“所有教学班均不可用”“缺少前置课”“检测到先修关系依赖环”“第 X 学期最低学分不足”等；界面将 `problems` 和 `warnings` 逐条展示，使用户能够定位是哪一类约束导致规划未完全满足。

7. 复杂度分析

记必修课程数为 N，选修候选课程数为 M，每门课程的平均教学班数为 S，单学期已排课程数为 P，学期数固定为 8。拓扑排序的复杂度为 O(N + E)，其中 E 为先修关系边数；安排一门课程最多尝试 8 个学期，复杂度约为 O(8·S·P)，整体复杂度约为 O((N + M)·8·S·P)

## 7. 图形化界面设计

本系统采用 Qt 6 Widgets 实现桌面图形界面，程序启动后创建 `QApplication` 对象并显示主窗口 `MainWindow`。界面相关代码主要位于：

```text
src/main.cpp
src/ui/main_window.h
src/ui/main_window.cpp
```


1. 界面设计目标

图形化界面主要服务于以下目标：

- 让用户能够选择培养方案并生成课程规划结果；
-  以直观的课程表形式展示第 1 至第 8 学期的课程安排；
-  支持按条件查询课程及教学班信息；
-  支持用户手动将指定教学班加入某一学期；
-  支持用户设置希望尽量避开的上课时间；
-  支持将生成的课程规划结果导出为 CSV 文件；
-  当规划失败或存在不满足的约束时，向用户显示相应提示。



2. 主窗口结构

系统采用单主窗口形式，主窗口类为 `MainWindow`。界面将不同功能划分为多个页面或区域，避免将所有信息堆叠在同一张页面中。

整体上可以概括为以下结构：

```text
MainWindow（主窗口）
├── 培养方案选择与规划操作区域
│   ├── 培养方案下拉框
│   ├── 生成课程规划按钮
│   └── 导出课程规划按钮
│
├── 功能页面区域（QTabWidget）
│   ├── 八学期课程表页面
│   ├── 课程查询页面
│   ├── 我的选课方案页面
│   └── 时间偏好页面
│
└── 提示与结果信息区域
    ├── 规划问题提示
    └── 时间偏好或约束未完全满足时的警告信息
```


3. 八学期课程表展示

系统为第 1 至第 8 学期分别创建课程表，并通过标签页切换不同学期的安排。

每个学期课表使用 `QTableWidget` 实现，表格的基本结构如下：

- 横向表头为：**时间、星期一至星期日**；
- 纵向按每天的 **13 个节次** 划分；
- 时间列显示每一节课的具体时间段；
- 课程按照其实际的星期和节次放入相应单元格；
- 跨多个节次的课程使用 `setSpan()` 合并单元格显示；
- 课程单元格中显示课程名称、教学班、上课周次、教室和教师等信息；
- 不同课程根据课程编号分配不同背景颜色，使课程块更容易区分。

这种课程表形式与常见高校课表接近，用户可以较直观地查看某门课程的上课时间、地点和任课教师。


4. 培养方案选择与生成规划

系统会读取 `data/major_profiles/` 目录下的培养方案 JSON 文件，并将文件名显示在培养方案下拉框中。

用户选择一个培养方案后，点击“生成课程规划”按钮，界面会完成以下工作：

- 获取当前选择的培养方案；
- 读取用户手动选课信息；
- 读取用户设置的时间偏好；
- 将培养方案、手动选课和时间偏好传递给规划服务模块；
- 接收算法模块返回的课程规划结果；
- 将结果填充到第 1 至第 8 学期的课程表中；
- 显示生成过程中出现的问题或警告信息。

这样，界面模块只负责收集用户输入和展示结果，具体的课程安排计算由后端规划模块完成。


5. 课程查询页面

课程查询页面用于浏览课程库中的课程及教学班信息。用户可以通过多个条件筛选课程，包括：

- 课程名称或课程编号关键字；
- 课程类别；
- 开课院系；
- 开课季节；
- 最低学分；
- 最高学分。

查询结果以表格形式显示。每一行对应一个具体教学班，表格中包含以下信息：

```text
课程编号、课程名称、教学班、课程类别、学分、院系、
开课季节、教师、教室、周次、上课时间
```

用户可以从查询结果中选择某个教学班，并进一步执行手动选课操作。

---

6. 手动选课页面

“我的选课方案”页面用于管理用户主动选择的课程。用户可以在课程查询结果中选中一个教学班，并指定安排到第几学期，再将其加入个人选课方案。

该页面支持以下操作：

- 查看已手动添加的课程；
- 取消某一门已选课程；
- 清空全部手动选课记录；
- 保存手动选课方案。

在用户添加课程前，系统会进行即时校验。例如：

- 是否重复选择同一基础课程；
- 课程和教学班是否存在；
- 目标学期是否合法；
- 课程开设季节是否与目标学期匹配；
- 是否与已手动选择的课程发生时间冲突；
- 是否超过学期最高学分；
- 是否违反先修课程关系。

如果校验失败，系统会弹出提示信息，并且不会将该课程加入个人选课方案。手动选课结果保存至：

```text
data/manual_course_plan.json
```

7. 时间偏好页面

时间偏好页面以“星期 × 节次”的表格形式展示一周内可设置的时间段。用户可以选择不希望安排课程的时间段，例如不希望在某天晚上上课。

当前界面的时间偏好属于“**尽量避开**”的软约束：

- 用户选择的时间段会保存为应尽量避开的上课时间；
- 算法在安排课程时会优先选择不与这些时间段重叠的教学班；
- 如果所有可行安排都无法避开该时间段，系统仍可能安排课程，并在结果中给出提示。

时间偏好信息保存至：

```text
data/time_preference.json
```

这种设计既允许用户表达个人偏好，也避免由于偏好限制过多而导致无法生成完整课程规划。

8. 课程规划导出

在成功生成课程规划后，用户可以点击导出按钮，将当前课程规划结果保存为 CSV 文件。

导出功能由 `ScheduleExporter` 模块完成，导出的内容包括课程名称、课程编号、学分、院系、教师、教室、上课周次、星期和节次等信息。导出时会使用 UTF-8 BOM，以提高文件在常见表格软件中打开时的中文兼容性。

该功能方便用户将规划结果保存、打印，或提交给他人查看。


8. 界面与其他模块的关系

界面模块不直接承担复杂的排课计算，而是作为用户与系统功能之间的交互层。其数据流可以概括为：

```text
用户操作
   ↓
Qt 图形界面（MainWindow）
   ↓
读取培养方案、手动选课和时间偏好
   ↓
PlanningService / Scheduler
   ↓
返回课程规划结果、问题与警告信息
   ↓
课程表展示、提示展示、CSV 导出
```

这种划分使界面展示逻辑与课程规划逻辑相对独立。后续如果需要调整排课算法，通常只需保持输入和输出数据结构一致，界面部分不需要进行大规模修改。
